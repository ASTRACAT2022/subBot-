# Руководство по API Remnawave и интеграции с ЮKassa

Это руководство поможет разработчикам понять, как устроен Remnawave ShopBot и как взаимодействовать с ключевыми компонентами системы: Remnawave API для управления VPN-пользователями и платежной системой ЮKassa для обработки платежей.

## Взаимодействие с Remnawave API

Модуль `src/shop_bot/modules/remnawave_api.py` является центральным элементом для управления пользователями и их подписками на VPN-серверах, работающих под управлением панели Remnawave.

### Основные концепции

- **Хосты и сквады (Hosts & Squads):** Вся работа с API привязана к `host_name`. Каждый хост представляет собой отдельный VPN-сервер (или группу серверов), зарегистрированный в боте. В терминах Remnawave, хост соответствует "скваду" (squad). У каждого хоста есть свой собственный URL API и токен авторизации, что позволяет боту централизованно управлять несколькими независимыми VPN-серверами.
- **Аутентификация:** Взаимодействие с API защищено с помощью Bearer-токена. Для каждого запроса к хосту, модуль находит соответствующий `remnawave_api_token` и отправляет его в заголовке `Authorization`.
- **Идентификация пользователя:** Основным идентификатором пользователя в системе Remnawave является его `email`. Бот генерирует уникальные email для каждого пользователя (например, `user12345@bot.local`), чтобы связать их с Telegram ID.

### Ключевые функции

Вот основные функции, которые используются для управления пользователями:

- **`ensure_user(...)`**
  - **Назначение:** Это главная функция для создания и обновления данных пользователя. Она работает идемпотентно: если пользователь с указанным `email` уже существует на данном хосте, функция обновляет его данные (например, продлевает срок действия подписки). Если нет — создает нового.
  - **Важные параметры:**
    - `host_name` (str): Имя хоста (сервера), на котором нужно выполнить операцию.
    - `email` (str): Уникальный email пользователя.
    - `squad_uuid` (str): UUID "сквада" на панели Remnawave, к которому будет привязан пользователь.
    - `expire_at` (datetime): Дата и время окончания подписки.

- **`get_user_by_email(...)` / `get_user_by_uuid(...)`**
  - **Назначение:** Получение информации о конкретном пользователе с сервера Remnawave по его email или UUID.

- **`delete_user_on_host(...)`**
  - **Назначение:** Полное удаление пользователя и его ключей с указанного хоста.
  - **Важные параметры:**
    - `host_name` (str): Имя хоста.
    - `user_uuid` (str): UUID пользователя в системе Remnawave.

- **`create_or_update_key_on_host(...)`**
  - **Назначение:** Это функция-обертка над `ensure_user`, которая упрощает процесс создания или продления ключа. Она принимает количество дней для добавления или конкретную дату окончания и сама выполняет необходимые вычисления перед вызовом `ensure_user`. Именно эта функция чаще всего используется в логике бота.

### Пример рабочего процесса

#### Создание нового ключа

1.  Пользователь в боте выбирает сервер (`host_name`) и тарифный план (например, 30 дней).
2.  Бот генерирует для него уникальный email, который еще не используется в системе, например `username_12345@bot.local`.
3.  Вычисляется дата окончания подписки: `текущая_дата + 30 дней`.
4.  Вызывается функция `remnawave_api.ensure_user(...)` (или `create_or_update_key_on_host`), куда передаются `host_name`, сгенерированный `email`, `squad_uuid` для этого хоста и вычисленная дата окончания.
5.  Remnawave API создает нового пользователя, генерирует для него ключ и возвращает в ответе всю информацию, включая `subscriptionUrl`.
6.  Бот сохраняет данные о ключе в свою локальную базу данных и отправляет `subscriptionUrl` пользователю.

#### Продление существующего ключа

1.  Пользователь выбирает свой активный ключ, который хочет продлить, и тарифный план (например, 90 дней).
2.  Бот находит данные этого ключа в своей локальной базе. Оттуда он берет `host_name` и `email`, привязанные к этому ключу.
3.  Вычисляется **новая** дата окончания подписки: `текущая_дата_окончания + 90 дней`.
4.  Снова вызывается `remnawave_api.ensure_user(...)` с теми же `host_name` и `email`, но с новой датой окончания.
5.  Remnawave API находит существующего пользователя по `email`, видит, что новая дата окончания позже текущей, и обновляет ее.
6.  Бот обновляет дату окончания в своей локальной базе данных и сообщает пользователю об успешном продлении.

## Интеграция с ЮKassa

Интеграция с платежной системой ЮKassa реализована для приема платежей от пользователей. Процесс разбит на три основных этапа: создание платежа, его оплата пользователем и обработка уведомления об успешной оплате (вебхук).

### Общая схема работы

1.  **Создание платежа:** Пользователь в боте выбирает тариф и способ оплаты "ЮKassa". Бот формирует запрос к API ЮKassa, создавая уникальный платеж.
2.  **Оплата:** Пользователь переходит по сгенерированной ссылке на сайт ЮKassa и совершает оплату.
3.  **Уведомление (вебхук):** После успешной оплаты ЮKassa отправляет на специальный URL (вебхук) в боте POST-запрос с информацией о платеже.
4.  **Обработка:** Бот принимает вебхук, проверяет его подлинность и выполняет бизнес-логику: вызывает API Remnawave для выдачи или продления ключа, обновляет данные в своей БД и сообщает пользователю об успехе.

### Ключевой элемент: `metadata`

Самая важная часть интеграции — это поле `metadata`, которое отправляется при создании платежа. В этом объекте бот "запоминает" всю необходимую информацию о заказе. Когда ЮKassa присылает вебхук, она возвращает эти `metadata` в неизменном виде. Это позволяет боту точно знать, какой именно заказ был оплачен.

Пример `metadata`:
```json
{
    "user_id": 123456789,
    "months": 3,
    "price": 500.00,
    "action": "extend",
    "key_id": 42,
    "host_name": "amsterdam_server",
    "plan_id": 3,
    "payment_method": "YooKassa"
}
```
Благодаря этим данным, после получения вебхука боту не нужно хранить состояние или пытаться угадать, что оплатил пользователь. Он просто читает `metadata` и выполняет соответствующее действие (`extend` ключа с `key_id=42` на сервере `amsterdam_server`).

### Файлы и функции

- **`src/shop_bot/bot/handlers.py`**
  - **`create_yookassa_payment_handler(...)`:** Эта функция отвечает за **шаг 1**. Она:
    - Собирает все данные о заказе (`user_id`, `plan_id`, `action` и т.д.).
    - Формирует объект `payment_payload`, включая `metadata`.
    - Использует библиотеку `yookassa` для отправки запроса и создания платежа.
    - Получает в ответ ссылку на оплату (`confirmation_url`) и отправляет ее пользователю в виде кнопки.

- **`src/shop_bot/webhook_server/app.py`**
  - **`yookassa_webhook_handler()`:** Эта функция реализует **шаг 3**. Она:
    - Объявлена с декоратором `@flask_app.route('/yookassa-webhook', methods=['POST'])`, который делает ее доступной извне для ЮKassa.
    - Принимает JSON-тело запроса.
    - Проверяет, что тип события — `payment.succeeded`.
    - Извлекает из тела запроса объект `metadata`.
    - Вызывает функцию `handlers.process_successful_payment`, передавая ей `metadata` для дальнейшей обработки.

- **`src/shop_bot/bot/handlers.py`**
  - **`process_successful_payment(...)`:** Это центральная функция для **шага 4**. Она вызывается не только для ЮKassa, но и для других платежных систем.
    - Получает на вход `metadata`.
    - Анализирует поле `action` ('new' или 'extend').
    - В зависимости от действия, вызывает соответствующие функции `remnawave_api.py` для создания или обновления ключа.
    - Обновляет данные в локальной базе данных (статистику пользователя, информацию о ключе).
    - Отправляет пользователю сообщение об успешной оплате и его ключ/обновленную информацию о подписке.
